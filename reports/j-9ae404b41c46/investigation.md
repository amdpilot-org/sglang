# Prefill ZMQ endpoint FD exhaustion

Upstream issue: https://github.com/sgl-project/sglang/issues/31766

Mirror issue: https://github.com/amdpilot-org/sglang/issues/2206

Base: `358c163250ad3b1f62939b01ce1314a0a31a0365`

The base implementation kept one PUSH socket and one monitor PAIR socket for
every endpoint ever observed by `CommonKVManager._connect`. The cache had no
size or age bound. A regression run against that implementation retained all
six unique test endpoints despite a limit of three; its raw output is at
`/tmp/amdpilot-repo-j-9ae404b41c46/evidence/failing-before.txt`.

The correction uses a configurable LRU limit (default 1024 endpoints), closes
the PUSH socket and monitor as a pair, and explicitly disables monitoring so
rapid eviction cannot collide with a stale autogenerated inproc monitor
address. The send path now owns its per-endpoint lock from socket lookup through
send; eviction skips an endpoint with an active sender and may temporarily
exceed the cap until an idle endpoint becomes available. Monitor construction
is atomic with cache insertion, and a failure closes the partially configured
PUSH socket.

A real PyZMQ probe sent 200 distinct endpoint names through the checked-out
`CommonKVManager._connect` with a cache limit of eight. It finished with eight
PUSH entries and eight monitor entries; `/proc/self/fd` started at 9, ended at
39, and peaked at 48. The complete registered disaggregation unit directory and
environment tests passed: 376 tests and 47 subtests.

The assigned AMD Instinct MI350X was visible, but no GPU execution was relevant
to this host-side descriptor lifecycle defect. The original 16x H800,
full-model, and multi-node workload was unavailable and remains unverified.

# Bounded MI300X DeepSeek V2 backend comparison

## Result

This study exercised the real `sglang.srt.model_executor.model_runner.ModelRunner` on one AMD Instinct MI300X (`gfx942`) with a locally generated two-layer DeepSeek V2 configuration and deterministic synthetic weights. It compared the installed AITER and Triton attention backends on identical inputs and weights, with CUDA graphs disabled.

All six workload cases passed the unchanged component gates against independent Torch formulas:

- Attention: cosine similarity >= 0.999, mean absolute error <= 0.02, maximum absolute error <= 0.10.
- MLP: cosine similarity >= 0.999, mean absolute error <= 0.02, maximum absolute error <= 0.10.

AITER was faster at batch sizes 1 and 2; Triton was faster at batch size 4. Cross-backend final-logit cosine similarity was at least 0.999996 and maximum absolute difference was 0.0009765625 in every case.

## Limitations

- This is a reduced two-layer DeepSeek V2 study, not a full-model quality or production-performance claim.
- Only AITER and Triton were compared; no fallback was relabeled as either backend.
- CUDA graphs were disabled, so this is an eager complete-block comparison.
- An exploratory nonstandard 80/64-dimensional MLA configuration failed Triton compilation with `Cannot make_shape_compatible: incompatible dimensions at index 1: 64 and 128`. The final study uses supported standard DeepSeek MLA dimensions.
- Read-only upstream context came from `sgl-project/sglang` issue 16255 and its related changes. No upstream issue, pull request, or comment was posted or changed.

# gfx942 merge-state execution evidence

## Scope

This follows the shared-prefix attention work described in sgl-project/sglang issue 1715 and the prior amdpilot-org/sglang issue 228 execution. It does not retry the original issue 228 trigger or duplicate closed upstream PR 5206. The uncovered case here is the ROCm execution representation of `merge_state_v2`: its Python wrapper and CUDA build expose the native op, but the ROCm build omitted both the kernel source and dispatcher registration.

## Installed-source baseline

The baseline was recorded before checkout changes in `/job/baseline-first.json`. It is evidence for the installed environment only, not for this branch.

- Interpreter: `/opt/venv/bin/python`; Torch `2.9.1+rocm7.2.0.git7e1940d4`.
- Installed SGLang: `0.5.18.dev20260826+g937af8538b` from `/sgl-workspace/sglang/python/sglang`.
- Installed `sgl-kernel`: `0.4.6.post1`; its ROCm `common_ops` library did not register `sgl_kernel::merge_state_v2`.
- FlashInfer was not installed, so the documented cascade API could not be invoked.
- The supported neighboring control was forced-flash SDPA on one MI300X. Profiling showed `aten::_scaled_dot_product_flash_attention` and native `attn_fwd`.
- FP16/BF16 SDPA control errors were bounded by `3.1e-4` and `2.3e-3` maximum absolute difference from independent float64 references. The six-case timing matrix ranged from `0.0244` to `0.0388` ms.
- First GPU control execution elapsed time was `0.02293` seconds.

## Change

- Add `csrc/attention/merge_attn_states.cu` to the ROCm extension source list.
- Register `merge_state_v2` in `common_extension_rocm.cc`.
- Use the ROCm extension utility header when compiling the kernel with HIP.
- Reject mismatched value dtype, non-float32 LSE dtype, wrong output shape, and wrong output device before native dispatch.
- Add focused native tests for documented FP32 dispatch, input/output aliasing, preallocated-address reuse, sentinel-protected output storage, and clear unsupported-contract failures.

The open upstream PR 29720 changes 64-bit indexing for very large tensors. This change does not duplicate that work.

## GPU results

Raw evidence is in `gpu-evidence.json` and is generated by `run_gpu_evidence.py` on one assigned MI300X (gfx942).

- Native module: `/tmp/sglang-cache-j-0a0ef4e9949d/lib/sgl_kernel/common_ops.cpython-310-x86_64-linux-gnu.so`.
- Actual dispatch symbols: `merge_attn_states_kernel<float, 128u>`, `merge_attn_states_kernel<__half, 128u>`, and `merge_attn_states_kernel<__hip_bfloat16, 128u>`.
- Matched FP32/FP16/BF16 values were generated once, cast to each execution dtype, and compared with an independent float64 PyTorch merge.
- All sentinel guard elements remained unchanged. Output aliasing and preallocated-address reuse were preserved.
- Unsupported mixed dtype, float64 dispatch, and wrong output shape all raised clear `RuntimeError` messages.
- The bounded timing matrix has nine cases (three dtypes by three shapes), with three warmups and twenty timed calls per case. Average times ranged from `0.0128` to `0.0300` ms.
- First rebuilt native merge execution elapsed time was `0.000895` seconds.

## Reproduction

Use the qualified Torch/ROCm stack and keep build output outside the repository:

```bash
CACHE=/tmp/sglang-cache-j-0a0ef4e9949d
mkdir -p "$CACHE/lib/sgl_kernel" "$CACHE/temp"
cd /job/sglang/python/sglang/kernels/aot
/opt/venv/bin/python setup_rocm.py build_ext \
  --build-lib "$CACHE/lib" --build-temp "$CACHE/temp" --parallel 4
cd /job/sglang
cp -a python/sglang/kernels/aot/python/sgl_kernel/. "$CACHE/lib/sgl_kernel/"
PYTHONPATH="$CACHE/lib" /opt/venv/bin/python -m pytest \
  python/sglang/kernels/aot/tests/test_merge_state_v2.py \
  -k 'float32_contracts or aliasing_and_static_storage_reuse or rejects_unsupported_contracts'
PYTHONPATH="$CACHE/lib" /opt/venv/bin/python \
  reports/j-0a0ef4e9949d/run_gpu_evidence.py
```

The build command may create HIP-hipified files under `python/sglang/kernels/aot`; remove only those generated files before creating a patch.

## Limitations

- No model weights were downloaded and no full model was run.
- FlashInfer cascade attention remains unavailable in this image; this work covers the native shared-prefix state merge used by the attention path, not a FlashInfer cascade integration.
- The static-storage check verifies stable preallocated addresses across calls. It does not perform a full CUDA/HIP graph capture/replay.
- Timing is a small bounded kernel matrix, not a serving benchmark.

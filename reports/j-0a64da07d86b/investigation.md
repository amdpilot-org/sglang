# Investigation: sunset Gemini Code Assist reference

Upstream issue: https://github.com/sgl-project/sglang/issues/33657

Mirror issue: https://github.com/amdpilot-org/sglang/issues/1770

## Finding

The warning reported in the issue was real, but it was not generated by code in
this repository. GitHub's issue-comment API identifies the referenced comment as
authored by `gemini-code-assist[bot]` and records `performed_via_github_app.slug`
as `gemini-code-assist`. The app posted the sunset warning on pull request
`sgl-project/sglang#33600` at `2026-08-04T20:57:20Z`.

At base commit `358c163250ad3b1f62939b01ce1314a0a31a0365`, all tracked files under
`.github/` were audited for both the app slug and its display name. Neither is
present. A GitHub code search of current upstream `main` likewise returned zero
matches for `gemini` under `.github`. Product-related Gemini references elsewhere
in the repository are unrelated and intentionally remain.

The public issue-comments endpoint returned exactly the reported sunset comment
and no later comments by that bot from the report timestamp through
2026-09-12. This is consistent with the warning's statement that the consumer
app ceased review activity. It does not prove whether an inactive installation
is still configured, because GitHub App installation settings are not exposed
by repository contents or public APIs.

## Reproduction and limitation

The original output was reproduced from the immutable public comment API:

```text
2026-08-04T20:57:20Z
https://github.com/sgl-project/sglang/pull/33600#issuecomment-5184535987
> [!CAUTION]
> The consumer version of Gemini Code Assist on GitHub has been sunset. All code review activity has officially ceased.
performed_via_github_app.slug: gemini-code-assist
```

Reproducing app behavior on a newly submitted upstream PR would require changing
or exercising upstream repository integration state. That is outside this task's
authority. If maintainers want to remove a still-visible inactive installation,
the action belongs in the upstream repository/organization GitHub App settings,
not in this source tree.

## Validation

`test_ci_reference.py` performs the repository audit and independently checks
three boundaries: the exact app slug is rejected, the human-readable app name is
rejected, and unrelated references to Gemini models are accepted. The audit
passes on the prepared base. No failing-before source regression exists because
the reported integration is absent from the checked-out implementation.

No GPU or native build was used: this issue concerns GitHub-hosted integration
configuration and has no model, kernel, compiler, or serving-path behavior.
